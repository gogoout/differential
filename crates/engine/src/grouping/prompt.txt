HOW TO SEE THE CHANGE

Nothing about the classes is in this prompt. Two commands put it in front of you:

  {{FETCH}} agent --doc {{DOC}}
      every class you must group, in full
  git diff {{BASE}} {{HEAD}} -- <path>
      what the change at that path actually says

RUN THE FIRST ONE ONCE. It is the whole class table and it does not need asking twice.
Per class it gives you the id, the hunk count, the file count, the disposition, the
exemplar's own path and line, then every member hunk with its file and line range, then
every file it touches. `defines:` is what the class introduces, `uses:` what it consumes
with the symbol behind each edge, `used by:` who consumes it.

SPEED MATTERS. This call takes minutes and almost all of it is you reading. Read what
decides a label, then stop. Do not walk every class in turn. Do not diff the whole
change. Do not open a file you can already label from its class entry.

READ WHAT A CLASS CLAIMS. Rating a class "skim" says every one of its hunks is the same
edit. A 9h class is a claim about nine hunks, not about the exemplar. The class entry
gives you all nine locations - the file and line range of each - and `git diff` on those
paths is how you check the claim. Only a class with MORE THAN ONE HUNK can be wrong about
it: for a `1h` class the exemplar is the whole class.

JUDGE A FILE BY ITS PATH BEFORE YOU OPEN IT. Every class in the id list must be grouped,
config, SQL, schema, fixture and documentation changes included. Grouping one is not the
same as reading one. The path tells you which it is, so spend your reading on the paths
that can change behaviour, and label the rest from their class entry.

Generated files - lockfiles, snapshots, build artefacts - are folded away before you see
them. No class you are given contains one, and their own class ids are not in the list.
`git diff` does not know that and will show you one if you ask, so do not ask: a path that
looks generated is generated, and reading it buys you nothing you can use.

Merging a class that defines something with a class that consumes a different group
leaves no valid reading order, so prefer not to. That is what `uses:` is for.
